Agent-native setup for the pi coding agent

No install script. Your agent reads the repo, inspects your machine, shows you a plan, backs up anything it overwrites, and verifies the result. The repo is the spec; the agent is the installer.

Read https://raw.githubusercontent.com/AungMyoKyaw/pi-setup/master/SETUP.md and follow it to set up my pi coding agent. Profile: recommended. Proceed. █

Paste it into your pi agent. That is the whole installer.

Why not a script

A shell script executes blindly. It assumes your OS, clobbers your existing settings.json, and fails opaquely.

An agent does what a careful human would: it deep-merges your settings instead of overwriting them, skips identity files you already have, backs up before every write, works from a URL or a local clone, and reports exactly what it did.

Markdown and YAML are easier to review, fork, and diff than any install script.

How it works

  1. 1. You paste the prompt. Your agent fetches SETUP.md and the manifest, then inspects your machine.
  2. 2. It shows you a plan — every file it will create, merge, or skip — and asks once, unless you pre-approved.
  3. 3. It applies the plan with backups, verifies the result, and reports what changed. Re-running the same prompt updates you; the procedure is idempotent.

Identity and memory files are skip-if-exists — the agent never overwrites yours.

What it never touches

  • → Credentials (auth.json), sessions, model caches, trust state — anything not in the manifest.
  • → Every overwrite is backed up to ~/.pi-setup-backups/ first.
  • → After setup you authenticate your own provider (/login inside pi). No keys ship in the repo.

Make it yours

Fork the repo, replace everything under files/ with your own config, edit setup.yaml to match, and run the audit before every push — it fails on leaked secrets, absolute home paths, and private machine files.

$ git clone https://github.com/AungMyoKyaw/pi-setup.git

$ cd pi-setup && ./scripts/audit.sh
