pi-setup

Agent-native setup for the pi coding agent

No install script. Your agent reads the manifest, checks your machine, plans each change, backs up overwritten files, installs only the selected profile, and verifies the result. Pi is required. Git is preferred for remote setup; Bun and Python gate optional components.

Paste into pi. The agent follows SETUP.md; VERIFY.md defines post-install checks.

Why not a script

A shell script executes blindly. It assumes your OS, clobbers your existing settings.json, and fails opaquely.

An agent does what a careful human would: it deep-merges your settings instead of overwriting them, skips identity files you already have, backs up before every write, works from a URL or a local clone, and reports exactly what it did.

Markdown and YAML are easier to review, fork, and diff than any install script.

How it works

  1. 1. You paste the prompt. Your agent reads SETUP.md and setup.yaml, checks pi, Git, Bun, Python, OS, and existing pi/agents directories.
  2. 2. It lists files to create, merge, copy, link, or skip. Without prior approval, it asks once before applying the plan.
  3. 3. It applies the selected profile, backs up overwritten files, verifies the install, and reports changes. Re-running refreshes managed files while preserving user identity files.

Recommended adds settings and prompts with global instructions/memory, three core extensions, five skills, four subagent definitions, and a system-prompt appendix. Core extensions redirect built-in file/shell tools away from home/root, show usage in the footer, and notify when requests finish. Core skills cover delivery workflows, grilling, and current developer documentation. Full adds quota display, image optimization, Second Brain retrieval, auto TODO/PLAN artifacts, Jev checkpoints, an opt-in SOUL.md, and skills for Exa search, Gmail, image metadata cleanup, browser automation, Scribd PDFs, design systems, Tauri apps, caveman style, and frontend quality. Jev requires Pi 1.0.4+; classifier credentials are optional. Missing optional prerequisites only skip affected components. Native tool concurrency needs no extra configuration. Subagent definitions do not install the subagent tool.

What it never touches

  • → Provider credentials (auth.json), model caches, trust/spend/run state, sessions, and memory/journal/. These are never inspected, printed, copied, or uploaded; unrelated files stay untouched.
  • → Every overwrite is backed up to ~/.pi-setup-backups/<UTC timestamp>/ before replacement. Settings are deep-merged; existing identity and memory files are skipped.
  • → Authenticate your provider with /login inside pi, then restart pi to load extensions and skills. No keys ship in the repo.

Make it yours

Fork the repo, replace files/ with your own config, edit setup.yaml, then run the local gates. The audit checks for leaked secrets, absolute home paths, and private machine files. make verify also runs formatting, extension typechecks/tests, and manifest/smoke regression tests; CI runs the same gate on pushes and pull requests.

$ git clone https://github.com/AungMyoKyaw/pi-setup.git

$ cd pi-setup && make verify
